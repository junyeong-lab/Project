# BR-B 최종 제출창 입력 문구 (검토용)

## 결과물 URL
https://vulnpriority-br-b.vercel.app/

## 짧은 확인 방법

**어디서 확인하나요?**

공개 앱 https://vulnpriority-br-b.vercel.app/ 에서 제품명·CVE 검색과 논문 기반 분석을 확인합니다. 기반 논문은 https://project-br-a.vercel.app/research.html 에 있고, BR-A 포트폴리오 대표작 자리 https://project-br-a.vercel.app/#projects 에 앱 링크를 연결했습니다. 계정이나 비밀번호는 필요하지 않습니다.

**무엇을 하나요? (3단계 이내)**

1. 새 시크릿 창에서 앱을 열고 OpenSSH·Log4j 같은 제품명으로 검색하거나 CVE-2024-3094를 검색합니다.
2. 검색 결과에서 CVE 하나를 선택해 CVSS v3.1 점수와 KEV 상태가 자동 입력되는지 확인합니다. 예를 들어 CVE-2024-3094를 선택하면 CVSS v3.1 10.0과 Critical이 표시됩니다.
3. '논문 근거로 점검 결과 보기'를 눌러 해당 심각도 구간의 KEV 등재 비율과 추가 점검 안내를 확인합니다.

**무엇이 보이면 통과하나요?**

검색 결과에 CVE 식별자와 공개 설명이 표시되고, 결과 선택 시 CVSS v3.1 점수(있는 경우)와 KEV 여부가 자동 반영됩니다. CVE-2024-3094의 경우 Critical 그룹의 논문 통계인 1.53628%(65/4,231건)가 표시됩니다. KEV 미등재는 안전 판정으로 처리하지 않습니다. CVSS에 11.0을 넣으면 안내 메시지가 나오고 앱이 멈추지 않습니다. 2024년 논문의 집단 통계를 개별 취약점의 악용 확률로 표시하지 않습니다.

**안 될 때는 어떻게 하나요?**

새로고침한 뒤 영문 제품명이나 정확한 CVE 번호로 다시 검색합니다. NVD·CISA 공개 API가 지연되거나 중단되면 오류 안내를 확인하고 재시도합니다. CVSS v3.1 점수가 없으면 추정치를 만들지 않습니다. 검색이 계속 어려울 경우, 실제 확인된 CVSS 점수와 KEV 상태를 직접 입력해 논문 통계 부분을 검증할 수 있습니다.

## AI와 내 판단 세 줄 (사용자 최종 검토 후 제출)

1. **AI에게 맡긴 일:** T10 논문의 CVSS 심각도별 KEV 등재 수치를 앱에 옮기고, NVD/CISA 공개 데이터를 이용하는 검색·자동 입력 기능, 오류 처리 및 테스트 코드를 작성하도록 했습니다.
2. **내가 직접 판단한 일:** 처음 만든 수동 점수 입력 방식은 일반 사용자가 CVE 번호나 CVSS 점수를 알기 어렵다는 문제가 있다고 판단했고, 제품명·키워드부터 검색해 취약점을 선택하는 방식으로 바꾸기로 결정했습니다. 검색·자동 입력·논문 분석과 공개 접근을 직접 확인했습니다.
3. **AI 제안을 따르지 않은 일:** 처음 제안된 CVSS 점수 수동 입력 중심의 v1 설계만으로 끝내지 않았습니다. 실제 사용자의 접근성을 높이기 위해 제품명 검색과 CVE 선택을 통한 자동 정보 입력을 추가하도록 요구했습니다.

## 사실 확인과 해석 제한

- 2024년 연구 표본: 32,102건, Critical 4,231건/KEV 등재 65건(1.53628%), Medium 15,993건/13건(0.08129%).
- 온라인 공개 데이터의 조회 시점은 연구 스냅샷과 다를 수 있습니다.
- KEV 미등재를 '안전' 또는 '악용 없음'으로 단정하지 않습니다.
- 동료 익명 반응: "개인이 만든 과제라기보다 실제 사람들이 사용하는 서비스처럼 보였다." (처음 사용하는 동료 1명이 설명 없이 직접 앱을 사용한 뒤 남긴 감상으로 사용자 확인; 전달받은 의미 보존 요약). 앱 하단과 BR-A 대표작에 익명으로 표시했습니다.
- 공식 ALEPH 합격/통과는 실제 제출·평가 후 확정됩니다.
